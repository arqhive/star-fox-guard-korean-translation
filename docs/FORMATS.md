# 파일 형식 정리 (스타폭스 가드, Wii U 일본판)

플래티넘게임즈 엔진이고 모든 값은 빅엔디언이다.

## CPK — `content/data000.cpk`, `data001.cpk`
- CRI CPK v7. `CPK `/`TOC `/`ETOC` 청크 안에 `@UTF` 표가 들어 있다(암호화 안 됨).
- TOC의 `FileOffset`은 `TocOffset` 기준 상대값, 파일 정렬은 2048바이트.
- 파일은 대부분 CRILAYLA 압축. `tools/cpk_lib.py`에 리더와 압축 해제가 있다.
- 번역 대상 텍스트는 전부 `data000.cpk`의 `ui/*.dat`와 `core/coreui.dat` 안에 있다.
- 재작성(`rebuild_cpk`)은 TOC의 `FileOffset`/`FileSize`/`ExtractSize`와 헤더의
  `ContentSize`/`EtocOffset`/`EnabledPackedSize`/`EnabledDataSize`만 제자리에서 고친다.
  교체 파일은 비압축으로 저장한다. **`TocCrc`는 계산 방식을 몰라 원래 값을 유지하며, 실기에서 문제없이 동작한다.**

## DAT — `ui_*.dat`
헤더: `DAT\0`, 파일 수, 오프셋표, 확장자표, 이름표(u32 이름 길이 + 고정 길이 이름), 크기표, 해시맵.
재작성 시 헤더와 해시맵은 그대로 두고 오프셋·크기만 갱신한다. 정렬은 `.wtp` 0x2000, 나머지 0x40, 끝 0x2000.

## MCD — `mess*.mcd` (텍스트)
헤더 10×u32: 메시지/심볼/글리프/폰트/이벤트의 오프셋과 개수.

| 구조 | 크기 | 내용 |
|---|---|---|
| 본문 | u16 배열 | (심볼 번호, 커닝 s16) 쌍. `0x8000` 끝, `0x8001`+폰트ID 공백, `0x8003`+n 버튼 아이콘 |
| 메시지 | 16B | 문단 오프셋, 문단 수, 순번, 이벤트 해시 |
| 문단 | 20B | 줄 오프셋, 줄 수, 문단 번호, 0, 폰트<<16 |
| 줄 | 24B | 본문 오프셋, 0, 길이, 길이, f32 자간, f32 줄간 |
| 심볼 | 8B | 폰트 u16, 문자(UTF-16) u16, 글리프 번호 u32 |
| 글리프 | 40B | 텍스처 해시, u1 v1 u2 v2, 폭, 높이, f32 3개 |
| 폰트 | 20B | id, f32 4개 |
| 이벤트 | 40B | 해시, 메시지 번호, 이름 32B |

- 본문 끝에 u16 0을 두고 4바이트 정렬, 각 표 뒤에는 4바이트 0이 붙는다.
- 심볼표는 (폰트, 문자) 순으로 정렬하고 심볼 번호 = 글리프 번호.

## WTA/WTP — 텍스처
- `.wta`가 정보, `.wtp`가 데이터. 헤더 @4에 u32 7개(버전, 개수, 오프셋표, 크기표, 플래그표, ID표, 정보 오프셋).
- 텍스처 정보는 GX2 서피스 구조(0xC0마다). 크기 필드는 `크기표 = imageSize + 0x11C`,
  서피스 +0x08 높이, +0x20 imageSize, +0x8C 레지스터 하위 13비트 = 높이-1.
- 포맷은 BC1(0x31/0x431), BC3(0x33/0x433), BC4/BC5, RGBA8(0x1A). tileMode 4 스위즐.
- MCD마다 전용 글리프 아틀라스(BC3)가 있다. **알파 = 글자 본체, RGB(회색) = 외곽선**(본체를 MaxFilter로 팽창).

## 그 밖에
- 그림 속 일본어는 `ui_msg_firsttime`의 계약서와 `ui_credit`의 손글씨 서명 2장뿐이다
  (텍스처 1,379장 전수 조사, `tools/tex_dump_all.py` + OCR + 육안 확인).
- 동영상(`content/movie/0000.usm`)에는 자막 트랙이 없고, 실행 파일의 일본어는 개발용 문자열뿐이다.
